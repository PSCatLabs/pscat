# Docs and site plan (issue #247, epic #246)

**Status: proposal. Nothing here has moved yet.** This page records the
audit of every human-facing document and site page, and the target
structure that #248 to #252 carry out. **The user approves it before #248 or
#250 starts.** The audit was taken against `main` at `1e1168e`
(2026-10-13).

Planned paths are written as `code`, not links, because most of them do
not exist yet. Real links in this file are relative to `docs/dev/`.

## The short version

- **README.** It shrinks from 1,358 lines to about 120. It keeps what pscat
  is, a picture, a quick start and links out. Nothing else.
- **`docs/guides/`.** The README's long library tour ("Making art") and its
  how-to sections become **13 user guides**, one per topic.
- **`docs/dev/`.** It holds contributor and design docs: `HANDOFF.md`,
  `ARCHITECTURE.md`, `VM.md`, `FONTS.md`, `CAPABILITIES.md`, and the library
  design docs now in `docs/`.
- **`docs/archive/`.** It holds history, kept intact: `NOTES.md` (frozen
  since #273), `ROADMAP.md`, `INIT.md`, the README's stage-by-stage "Status"
  log, and two one-off writeups.
- **The repo root** keeps only `README.md`, `CLAUDE.md`, `AGENTS.md`,
  `SDLC.md`, the Cargo files, `build.rs`, and the `notes/` directory.
- **Site navigation:** Home, Learn, Gallery, Fonts, Playground, Guides,
  For agents, Contribute, GitHub.
- **Gallery.** It splits into two tiers. **Art** holds the 27 pieces in 8
  categories. **Specimens and examples** holds the 32 library demos now on the site.
- **Reference map.** The moves touch **288 references (on 281 lines) in 95 files**,
  mostly code comments. They are listed one by one in the
  [appendix](#appendix-reference-map). Three of them are load-bearing, so
  #248 and #249 must fix them in the same PR:
  - `tests/headline.rs` reads a code snippet out of `README.md`;
  - the `/work-issue` skill and `CLAUDE.md` both point at `HANDOFF.md` and
    `NOTES.md`;
  - `scripts/build_site.sh` copies a hard-coded file list.

## Decisions for the user

Each one has a recommendation. Approving the plan approves these
recommendations unless you say otherwise.

1. **`HANDOFF.md` moves to `docs/dev/HANDOFF.md`.** `CLAUDE.md` says to read
   it first, and the `work-issue` and `sdlcify` skills mention it.
   **Recommendation: move it.** #249 fixes the 16 references to it in the
   same PR. Keeping it at the root would leave the one big agent-facing file
   at the front door.
2. **`notes/` stays at the root, and `NOTES.md` moves to
   `docs/archive/NOTES.md`.** The `work-issue` skill hard-codes the
   `notes/<N>-<slug>.md` path, and every PR writes there.
   `notes/README.md` already calls `NOTES.md` "frozen history".
   **Recommendation: yes.**
3. **The library design docs move to `docs/dev/design/`.** These are
   `DRYMEDIA.md`, `PAINT_LOADING.md`, `WATERCOLOR.md` and
   `CANVAS_SURFACE.md`, with their image and prototype folders. They cause
   the most reference churn: about 80 references, nearly all in comments in
   `lib/`, `src/`, `tests/`, `examples/` and `build.rs`.
   **Recommendation: move them.** The edit is mechanical (`sed` over exact
   paths), and it leaves `docs/` holding only `guides/`, `dev/` and
   `archive/`. The alternative is to leave them where they are and accept
   a mixed `docs/` folder.
4. **Guides reach the site as links to the GitHub-rendered Markdown, not as
   mirrored HTML.** `build_site.sh` has no Markdown-to-HTML step, and adding
   one means a new dependency and a second copy that can drift.
   **Recommendation: link.** The site gets a `guides.html` index page with
   one card per guide, each linking to the Markdown file on GitHub. If a
   rendered copy is wanted later, a converter can be added without moving
   anything.
5. **The gallery has two tiers, and each art piece has one primary
   category plus optional tags.** See [Gallery taxonomy](#gallery-taxonomy).
   **Recommendation: yes.**

## 2. Target layout

```
README.md  CLAUDE.md  AGENTS.md  SDLC.md     the front door and agent entry points
notes/                                        per-issue working notes (stay; the skill writes here)
docs/
  guides/      user guides: how to use pscat and each art library
  dev/         contributor docs: HANDOFF, ARCHITECTURE, VM, FONTS, CAPABILITIES,
               PS_LIBRARY_COUPLING, SELFTEST, GS_CHECK_INVENTORY, DOCS_PLAN
    design/    library design docs and their evidence (drymedia, paint loading,
               canvas surface, watercolor)
  archive/     history, kept intact: NOTES, ROADMAP, INIT, STATUS_LOG,
               one-off writeups
```

**Where new docs go.** Other tickets keep adding docs while this epic runs,
so these rules apply from approval onward, before the moves have happened:

- A new library **design doc** goes in `docs/dev/design/`.
- A new **user guide** goes in `docs/guides/`.
- A new **one-off writeup**, such as the record of a decision, goes in
  `docs/archive/`.
- **Per-issue notes** go in `notes/`, as they do today.

This covers the typewriter study (#210) and mathkit (#237). Neither had
added docs on `main` at `1e1168e`. When they land, the typewriter study goes
in `docs/dev/design/`, and mathkit's usage goes in a section of
`docs/guides/dry-media.md`.

### Manifest shape (a suggestion for #251)

There is one entry per item, in `gallery/manifest.json`. JSON is
suggested because `build_site.sh` runs on stock Ubuntu with `python3`
available. Each entry has these fields:

- `id`
- `title`
- `tier`
- `category`
- `tags`
- `source` (the `.ps` path)
- `render` (the PNG path)
- `page` (the size, for example `700x700`)
- `libraries`
- `issue`
- `blurb`
- `reference` (optional)

#251 owns the final schema. Whatever it is, it replaces both the hard-coded
render list in `build_site.sh` and the piece table in `gallery/README.md`.
