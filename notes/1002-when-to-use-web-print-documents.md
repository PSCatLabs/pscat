## when-to-use: documents from a web page, and many documents from one template (issue #1002, 2026-11-04)

**What was built.** Two sections in `docs/guides/when-to-use-pscat.md`, and a
shorter version of each in `site/when-to-use.html`, plus two decision-table
rows on both:

- "Documents from a web page, the same for every user": pscat's WebAssembly
  build as a web app's document engine. One run makes the preview, the
  download and the print. It gives the same bytes for the same template and
  data, needs no server, account, GPU or model, and is not sampled.
  [PSCatLabs/print-shop](https://github.com/PSCatLabs/print-shop) is the
  worked example, presented as something built on pscat. The claims are
  limited to its tests (`tests/render.test.mjs`) and `docs/VERIFICATION.md`,
  and the section lists its stated limits. It says print-shop pins a
  pre-release engine until its #16.
- "Many documents: write the template once, render each one": the owner's
  operational-cost argument (added mid-task through the coordinator). Image
  models and LLM calls are described in general terms only, dated November
  2026, with no prices or benchmarks; pscat's figures are measured.

**Release wording.** SVG/PDF from wasm is "on `main` since #1003
(2026-11-04), not in 0.7.0-rc.3 or any earlier release". Tags checked with
`git ls-remote --tags origin 'v0.7.0*'` (rc.1 to rc.3, all before #1004).
Released builds give a page RGBA pixels, not PNG. HANDOFF names the two
sentences to update later.

**Measurement** (2026-11-04, Apple M4 Mac mini `Mac16,10`, 10 cores, 16 GB,
macOS 15.7.7; load average 3 to 7 from other agents during the runs). The
binary is a native `cargo build --release` of `main` at `c1a2852`, and the
wasm is `scripts/build_wasm.sh` from the same commit, under Node 24.14.0.
The jobs were generated by print-shop's own `compileMenu`/`compileCard` (its
checkout at `503b7ec`, imported read-only), Classic Bistro template, default
parameters: the example CSV menu, `makeMenu(40)`, `makeMenu(500)` and the
business card. Its templates `run` `lib/functional.ps`, which is not on pscat
`main` (print-shop#16 removes the dependency), so the file was taken from
print-shop's pin `e8d6cf2` and inlined. Native runs are one
`pscat --page WxH ... job.ps` process each (process start included). Wasm
runs are repeated `run()` calls in one instance (instantiation excluded).

1000 personalized two-sided cards (different name, role, email, phone and
address each), one run each:

```
1000 cards pdf, one process each, sequential: wall 9.99 s, cpu 8.86 s
1000 cards pdf+svg, one process each, sequential: wall 11.15 s, cpu 10.02 s
1000 cards pdf, wasm in one Node instance: wall 7.13 s, cpu 7.20 s
1000 cards pdf+svg, wasm in one Node instance: wall 8.72 s, cpu 8.68 s
```

The guide rounds these figures. An earlier pass under a load average of 18
gave noisier numbers, including a card PDF-only median slower than PDF+SVG,
and was discarded. Wasm and native bytes were also compared on these four
jobs: every SVG page and the PDF were identical. The benchmark harness
lived in the session scratchpad and is not committed. The method above is
enough to repeat it.

**Not done.** No timing of image models or LLMs (the owner asked for none).
No whole-machine parallel throughput (independent jobs would parallelise,
but it was not measured, so it is not claimed). No edit to print-shop.
